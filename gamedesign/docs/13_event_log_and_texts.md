# 13. Журнал событий и точки решения

Цель: игрок должен понимать, что происходит во время автодвижения героя, но игра не должна превращаться в постоянный диалог.

## Решение

В первом playable нужен **журнал событий**.

Журнал показывает результат обычных событий строками:

```text
Саксаул: путник находит тень и хворост. Силы +1, Запасы +1
Звериная тропа: проверка Body провалена. Силы -2. Слава +1.
Круг завершен. Аул виден в дымке.
```

Пауза нужна не для каждого события, а только для решений игрока.

## Что идет в лог

| Событие | Лог | Пауза |
| --- | --- | --- |
| Получение ресурса | Да | Нет |
| Срабатывание безопасного тайла | Да | Нет |
| Проверка тайла, успех | Да | Нет |
| Проверка тайла, провал | Да | Нет |
| Потеря/восстановление Сил | Да | Нет |
| Конец круга | Да | Да, если есть выбор карты |
| Получение карты | Да | Да, если это FTUE или выбор/постановка |
| Появление Последней Тамги | Да | Да |
| Подбор Последней Тамги | Да | Нет |
| Смерть героя | Да | Да |
| Новый наследник | Да | Нет |

## Что является точкой решения

Точки решения:

- первая обучающая карта `Саксаул`;
- выбор 1 карты из 3;
- размещение выбранной карты;
- конец круга с выбором;
- смерть и результат забега;
- запуск нового наследника;
- редкое крупное событие после MVP.

Не точки решения:

- обычный ресурс;
- обычный успех/провал проверки;
- автоматическое лечение;
- автоматический урон;
- подбор Тамги.

## `log.tsv`

Да, для тона игры тексты лучше вынести в отдельную таблицу, которую ведет GDD.

Предлагаемый формат:

```text
event_id | tone | template
```

Где:

- `event_id` - ключ события;
- `tone` - тип строки для цвета/звука/UI;
- `template` - текст с плейсхолдерами.

Плейсхолдеры:

```text
{tile}
{stat}
{diff}
{supplies}
{wisdom}
{glory}
{stamina}
{circle}
{hero}
```

## Тон

Текст должен быть:

- коротким;
- меланхоличным;
- понятным по числам;
- без длинной прозы;
- без арабской сказочности;
- ближе к памяти рода, песку, костру, следам, имени.
