# 23. FTUE analysis and improvement plan

Цель: улучшить FTUE после первого production-script и сделать его понятнее для игрока, а не только подробнее для разработки.

## Короткий вердикт

FTUE движется в правильную сторону:

```text
аул -> герой сам идет -> карта -> placement -> отложенный эффект -> круг -> выбор -> риск -> Тамга -> наследник
```

Но главный риск сейчас - перегрузка. В первые 10 минут мы пытаемся показать почти весь core MVP. Это нормально для playable proof, но опасно для игрока: если одновременно объяснять `road_buffer`, `roadside`, `field`, руку карт, лог, аул, смерть, Тамгу и наследника, игрок запомнит не причинность, а шум.

Решение: FTUE нужно разделить на **обязательные уроки** и **видимые, но не объясняемые системы**.

## Что FTUE обязан доказать

| Приоритет | Что доказать | Как игрок это понимает |
| --- | --- | --- |
| P0 | Герой из аула | Он физически выходит от костра и идет к дороге. |
| P0 | Герой идет сам | Первые 2-3 клетки проходят без input. |
| P0 | Игрок влияет картами | Игрок сам ставит Саксаул. |
| P0 | Тайлы работают позже | Саксаул помогает только при будущем проходе. |
| P0 | Дорога, buffer и build-зона разные | Road/path не подсвечиваются; `roadside_build` пульсирует. |
| P1 | Есть разные placement-типы | После первого круга Юрта/Камень подсвечивают `field`, След подсвечивает `roadside`. |
| P1 | Риск выгоден, но опасен | Звериная тропа дает Славу или урон/часть награды; Волчий след проявляется как маркер на дороге. |
| P1 | Смерть не конец | Тамга остается на карте, аул сохраняет часть результата. |
| P2 | Новый наследник продолжает путь | Новый путник выходит из того же аула и подбирает Тамгу. |

## Что не объяснять в первые минуты

| Система | Что делать в FTUE |
| --- | --- |
| Полные синергии | Не объяснять. Только намек через роли карт. |
| Прокачка аула | Показать сохранение ресурсов, но не открывать дерево улучшений. |
| Реликты и экипировка | Панель героя может иметь пустые слоты, но без обучения. |
| Камера большого мира | В первой постановке не требовать скролла. Показать скролл только когда `field` выбран. |
| Оазис | Не использовать в обучении. Можно оставить в каталоге как будущую сильную находку. |
| Полные формулы проверок | Показывать коротко: `Body`, успех/провал, результат. |

## Новый teaching budget

Правило: **одно новое понятие на один ключевой момент**.

| Фаза | Учим | Не учим |
| --- | --- | --- |
| A. Дом и путь | аул, герой, автодвижение | карты, field, смерть |
| B. Первое влияние | Саксаул, roadside, отложенный эффект | выбор из 3, field, риск |
| C. Первый выбор | разные роли карт, разные placement-зоны | синергии, экономика аула |
| D. Риск и наследие | проверка, Тамга, новый наследник | полноценный roguelite meta |

Если в фазе появляется лишнее UI-объяснение, его нужно убрать или сделать фоном без текста.

## Улучшение 1: активная цель на экране

Каждая фаза должна иметь одну короткую цель. Это не tutorial pop-up на пол-экрана, а маленькая строка задачи рядом с активной UI-зоной.

Для интро действует отдельное правило темпа: не больше 6 секунд до появления/подъема первого путника и новый визуальный сигнал каждые 1-1.5 секунды. Красота не должна задерживать игру. Когда путник сделал первый шаг от костра, это уже gameplay-state с locked input, а не заставка.

| Состояние | Цель на экране |
| --- | --- |
| `ftue_03_aul_reveal` | `Отправиться в путь.` |
| `ftue_04_aul_exit` | `Смотри: путник выходит из аула.` |
| `ftue_06_autowalk_hint` | `Путь ведет героя сам.` |
| `ftue_08_card_saxaul_found` | `Выбери карту Саксаул.` |
| `ftue_09_saxaul_place_prompt` | `Поставь Саксаул в подсвеченную клетку.` |
| `ftue_11_saxaul_triggered` | `Саксаул помог при будущем проходе.` |
| `ftue_13_first_choice_opened` | `Выбери, что важнее: запас, память или риск.` |
| `ftue_14_first_choice_place_prompt` | `Поставь карту в подсвеченную зону.` |
| `ftue_20_run_result` | `Сохрани результат в аул.` |
| `ftue_22_last_tamga_pickup` | `Тамга прошлого героя стала наградой.` |

## Улучшение 2: UI lock matrix

Для Code важно не только что показать, но и что заблокировать.

| Состояние | Карты | Карта мира | Камера | Лог | Правая панель |
| --- | --- | --- | --- | --- | --- |
| `ftue_00_boot` | скрыты | скрыта | locked | скрыт | скрыта |
| `ftue_03_aul_reveal` | скрыты | только костер/аул clickable, pointer над аулом | locked на аул | 1 строка | скрыта/пустая |
| `ftue_04_aul_exit` | скрыты | view only | locked аул->дорога | active | герой visible |
| `ftue_06_autowalk_hint` | disabled tray | view only | soft follow | active | герой visible |
| `ftue_08_card_saxaul_found` | only Саксаул | view only | locked nearby slots | active | visible |
| `ftue_09_saxaul_place_prompt` | Саксаул selected | only valid roadside clickable | locked placement area | active | visible |
| `ftue_13_first_choice_opened` | 3 choices clickable | dimmed | locked overview | active | visible |
| `ftue_14_first_choice_place_prompt` | selected card | only valid placement clickable | may pan to field | active | visible |
| `ftue_20_run_result` | hidden | view only | aul + tamga relation | active | result panel |

Ошибочный input не должен открывать модалку. Только короткий feedback в месте клика и строка в лог.

## Улучшение 3: первая постановка должна быть без скролла

Первый Саксаул должен ставиться в видимый `roadside_build` слот. Нельзя требовать от игрока камеры/скролла до того, как он понял:

```text
карта -> valid slot -> поставленный тайл -> будущий эффект
```

Камеру большого мира раскрываем позже:

```text
выбор Юрты/Камня Тамги
-> камера чуть отъезжает
-> field slots подсвечены
-> игрок видит, что пустыня больше первого экрана
```

## Улучшение 4: road buffer должен учиться через отказ

Игроку не нужно заранее читать "road buffer no-build". Он должен увидеть:

1. `road_path` не подсвечивается.
2. `road_buffer` не подсвечивается.
3. При ошибочном клике по buffer появляется короткий отказ:

```text
Кромка пути: строить нельзя.
```

Этот отказ должен быть маленьким bubble у клетки, не модалкой.

## Улучшение 5: первый риск не должен отменять безопасный выбор

Если игрок выбрал Юрту или Камень Тамги, а затем игра все равно открывает риск на дороге, это может ощущаться как обман. Нужно визуально объяснить:

```text
твой тайл помог
-> но впереди мир открыл угрозу
```

Порядок второго круга:

1. Сначала показать пользу выбранной карты или Саксаула.
2. Потом показать затемнение/след впереди.
3. Потом разрешить проверку.

Так игрок понимает: его выбор сработал, но мир не стал безопасным навсегда.

## Улучшение 6: смерть/почти смерть как FTUE-допущение

В финальной игре Последняя Тамга должна быть следом смерти. Для playable можно временно разрешить Тамгу при "почти смерти", но это нужно явно маркировать:

```text
FTUE demo rule: если герой не умер до 8-й минуты, scripted pressure доводит его до 1 Силы и создает обучающую Тамгу.
Production rule: Тамга появляется при смерти.
```

Так мы не ломаем долгосрочный смысл системы.

## Улучшение 7: тексты должны быть финальными и короткими

Тон: память рода, песок, следы, костер. Не сказка и не системная канцелярия.

## P0 улучшения прямо сейчас

1. Добавить на сайт FTUE-анализ: "что учим / что не учим / риск перегруза".
2. Добавить в `22_ftue_production_script.md` teaching budget и UI lock rules.
3. Обновить brief для Code: сначала реализовать только фазы A-B как must-pass, затем C-D.
4. Визуально показать на сайте, что первый Саксаул не требует скролла, а `field` раскрывается позже.

## Следующий дизайн-шаг

После этих правок нужно отдельно расписать **Segment B в production detail**:

```text
карта Саксаул в руке
-> selected state
-> valid roadside glow
-> invalid road/buffer feedback
-> card flies to slot
-> linked road cell highlight
-> future trigger
```

Это самая важная часть FTUE, потому что именно здесь игрок впервые делает действие.
