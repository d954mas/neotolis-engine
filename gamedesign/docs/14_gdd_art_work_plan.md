# 14. План GDD/арт-работы

Цель: пока Code делает playable core, GDD должен подготовить контент, визуальные ориентиры и критерии ревью, чтобы первая playable-версия не была просто техническим тестом.

## Роль GDD сейчас

Я не трогаю реализацию core. Моя зона:

- смысл игрового цикла;
- контент карт и тайлов;
- тексты журнала;
- FTUE;
- фейкшоты экранов;
- критерии ревью playable;
- визуальный стиль;
- план следующей итерации после первого теста.

## Главный вопрос текущей фазы

```text
Игрок чувствует, что он играет,
или просто смотрит на автоматического путника?
```

Все GDD-решения сейчас должны помогать ответить на этот вопрос.

## Что делать параллельно с Code

### 1. Фейкшоты экранов

Нужно сделать 4 визуальных ориентира:

| Фейкшот | Что показывает |
| --- | --- |
| `core_run` | Аул, кольцевая дорога, герой, свободные roadside-слоты, журнал событий. |
| `card_place` | Игрок выбрал карту, доступные слоты подсвечены. |
| `card_choice` | Конец круга, выбор 1 из 3 карт. |
| `death_tamga` | Смерть, Последняя Тамга, ресурсы аула, кнопка нового наследника. |

Это не финальный UI. Это visual target для проверки читаемости.

### 2. Первый контент карт

Нужно подготовить не просто 6 текущих тайлов, а первый контентный набор:

- первые 6 карт из `tiles.tsv`;
- еще 4-6 карт-кандидатов для следующего шага;
- роли карт: помощь, память, риск, контроль риска, синергия;
- короткий текст карты;
- что игрок должен понять, когда берет карту.

### 3. Журнал событий

`log.tsv` уже начат. Следующий шаг:

- расширить события под FTUE;
- добавить строки для выбора карт;
- добавить строки для аула;
- добавить строки для смерти и нового наследника;
- проверить тон: коротко, меланхолично, без сказочной перегрузки.

### 4. Первый 10-минутный сценарий

Нужно расписать:

```text
минута 0-1: интро и первый ресурс
минута 1-2: Саксаул и постановка
минута 2-3: первый круг
минута 3-5: выбор карты и первый риск
минута 5-7: смерть или почти смерть
минута 7-10: новый герой и Тамга
```

Это станет главным сценарием ревью.

### 5. Ревью playable

Когда Code даст билд, GDD проверяет:

- понятно ли, что герой идет сам;
- понятно ли, куда ставить карту;
- видно ли, что Саксаул помог позже, после постановки;
- ощущается ли риск второго круга;
- смерть воспринимается как прогресс рода;
- журнал помогает понимать события;
- карта не выглядит как пассивная симуляция.

## Приоритеты GDD

### Сейчас

1. Фейкшоты.
2. Первые карты.
3. Расширенный `log.tsv`.
4. Первый 10-минутный сценарий.
5. Чеклист ревью playable.

### После первого playable

1. Ревью темпа.
2. Ревью читаемости карты.
3. Баланс первого круга.
4. Баланс смерти.
5. Решение: добавлять синергии или сначала улучшать карту/руку.

## Что не делать сейчас

Не делать:

- полный большой GDD на десятки систем;
- сложную экономику аула;
- процедурную дорогу как основную фичу;
- много наследников;
- длинный сюжет;
- большое дерево апгрейдов.
