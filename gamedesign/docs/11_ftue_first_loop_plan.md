# 11. FTUE и первый playable-круг

Цель: получить минимальный проверяемый билд, где игрок понимает core loop за 1-2 круга.

## Что уже зафиксировано

Да, GDD фиксирует такой кор:

```text
герой идет сам
-> герой находит ресурсы и карты
-> игрок ставит карты в допустимые buildable-зоны пустыни
-> тайлы помогают или повышают риск
-> герой умирает или возвращается в аул
-> аул получает часть результата
-> новый герой выходит снова
```

## Что нужно объяснить Code/Claude

### Типы тайлов

Для первого playable не нужен полный набор Loop Hero. Нужны 3 понятных типа.

| Тип | Где живет | Как действует |
| --- | --- | --- |
| `road_event` | Клетка дороги | Срабатывает, когда герой наступает на клетку. |
| `roadside_tile` | Ближняя buildable-зона за road buffer | Влияет на ближайшие дорожные клетки или будущие проходы. |
| `field_tile` | Дальний field большого мира | Работает через радиус, соседство, доход за круг, ауры или синергии. |
| `memory_tile` | Особый знак/Тамга | Связан со смертью, наследием, аулом и редкими эффектами. |

### Режимы действия тайлов

| Режим | Что значит | Пример |
| --- | --- | --- |
| Постоянный | Эффект есть, пока тайл стоит | Камень Тамги дает Мудрость/память. |
| При входе | Герой проходит клетку и получает эффект | Буря делает Spirit-проверку. |
| При соседстве | Тайл влияет на соседние клетки/зону | Саксаул рядом с Юртой дает малую стоянку; roadside-тайл может влиять на ближайшую road cell. |
| По кругу | Эффект срабатывает раз в круг | Юрта дает Запасы при возвращении. |
| Трансформация | Соседство превращает тайлы в новый тайл | Оазис + Юрта = Стоянка. |
| Плохая синергия | Жадность игрока создает опасность | 2 Звериные тропы рядом = Стая. |

## План FTUE

### 0. Интро

Экран темный.

Текст:

```text
Песок стирает следы.
Род хранит имена.
Один наследник должен пройти кольцо.
```

Появляется:

1. пустыня;
2. аул;
3. костер;
4. первый путник у костра;
5. короткий переход от аула к дороге;
6. кольцевая дорога.

Важно: герой не должен просто появляться на дороге. В первом кадре он выходит из аула/стойбища, доходит до первой клетки дороги и только после этого начинает loop.

```text
aul_exit -> road_entry -> loop_walk
```

### 1. Первые шаги без выбора

Путник сначала выходит из аула и попадает на дорогу. Затем он сам проходит 2-3 клетки.

Цель: игрок видит, что он не управляет движением.

Дополнительная цель: игрок понимает, что аул - дом героя, точка старта и будущая точка возвращения.

На одной клетке появляется простой лог:

```text
Запасы +1
```

### 2. Первая карта

После 2-3 клеток герой получает гарантированную карту:

```text
Саксаул
```

Игра ставит паузу.

Подсвечивается одна допустимая buildable-ячейка за road buffer.

Игрок ставит Саксаул.

### 3. Первый эффект тайла

Когда герой проходит рядом с Саксаулом или через связанную дорожную клетку:

```text
Саксаул: Силы +1, Запасы +1
```

Цель: игрок понимает, что карта помогла не сразу кнопкой, а через мир.

### 4. Конец первого круга

Герой возвращается в аул.

Игра ставит паузу и дает выбор 1 из 3 карт:

```text
Юрта
Камень Тамги
Звериная тропа
```

FTUE подсказывает:

```text
Безопасность, память или риск.
```

### 5. Второй круг

Игрок ставит одну выбранную карту.

Во втором круге должен появиться первый риск:

```text
Звериная тропа
Проверка Body
Успех: Слава +2
Провал: Силы -2, часть награды
```

Если игрок выбрал не Звериную тропу, риск можно дать scripted road_event на дороге.

### 6. Первая смерть или почти смерть

Для проверки кора нужен сценарий, где герой может умереть быстро.

Вариант для debug/FTUE:

```text
после второго круга появляется Песчаная буря
или несколько проверок подряд снижают Силы до 0
```

Смерть:

1. движение останавливается;
2. на клетке смерти появляется Последняя Тамга;
3. показывается результат забега;
4. часть ресурсов уходит в аул;
5. игрок нажимает "Новый наследник";
6. новый герой выходит из аула.

### 7. Подбор Тамги новым героем

Новый герой идет по кругу.

Если он доходит до клетки с Последней Тамгой:

```text
Последняя Тамга: Мудрость +X, Слава +Y
```

Тамга исчезает.

Цель: игрок понимает, что смерть стала целью следующего забега.

## Проверочный сценарий

Минимальная проверка первого playable:

1. Запустить игру.
2. Увидеть интро или сразу аул/путь, если интро еще не готово.
3. Герой выходит из аула/стойбища.
4. Герой доходит до первой клетки дороги.
5. Герой сам идет по loop.
6. Герой получает ресурс.
7. Герой получает карту Саксаул.
8. Игрок ставит Саксаул.
9. Саксаул срабатывает.
10. Герой завершает первый круг.
11. Игрок выбирает 1 из 3 карт.
12. Второй круг дает риск.
13. Герой умирает или почти умирает.
14. При смерти появляется Последняя Тамга.
15. Аул получает часть ресурсов.
16. Игрок запускает нового героя.
17. Новый герой может подобрать Тамгу.

Если эти 17 пунктов работают, core MVP доказан.

## Что можно резать

Если времени мало:

- убрать озвучку;
- заменить интро статичным fade-in;
- оставить только одну обучающую карту `Саксаул`;
- выбор 1 из 3 заменить фиксированной следующей картой;
- апгрейд аула заменить числом "Ресурсы аула";
- Тамгу сделать простой меткой без сложных реликтов.

Нельзя резать:

- автодвижение;
- постановку карты игроком;
- эффект поставленного тайла;
- смерть;
- ресурс аула после смерти;
- нового героя после смерти.

## Что просить у Code следующим

Приоритет реализации:

1. `cards.tsv` или временная модель "карта 1:1 с tile_id".
2. Рука карт до 5.
3. Гарантированный дроп `Саксаул` в FTUE.
4. Режим размещения карты в допустимую buildable-клетку по `placement`: `roadside` или `field`.
5. Применение эффекта тайла при будущем проходе.
6. Выбор 1 из 3 карт после круга.
7. Смерть -> Последняя Тамга -> ресурсы аула -> новый герой.

## Решение

Начинаем не с полного аула и не с полной экономики.

Начинаем с проверки:

```text
1-2 круга
-> постановка карты
-> риск
-> смерть
-> ресурс аула
-> новый герой
-> подбор Тамги
```
