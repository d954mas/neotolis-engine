# 12. План для разработчика: playable core

Цель: как можно быстрее дать игроку поиграть и почувствовать геймплей, а не только увидеть симуляцию.

## Контекст ревью с Code

Code уже подтвердил:

- герой авто-идет по loop-дороге;
- тайлы срабатывают;
- проверки работают;
- Силы могут упасть до 0;
- смерть и retry уже есть;
- текущие `balance.ini`, `heirs.tsv`, `tiles.tsv` загружаются.
- карта сейчас строится через `map_zone_*`, `map_aul_*`, `map_bends_*`.

Code задал GDD-вопросы:

1. дорога фиксированная или процедурная;
2. нужна ли колонка `placement`;
3. сколько build-слотов вокруг дороги.

## GDD-решения после ревью

| Вопрос | Решение для MVP |
| --- | --- |
| Дорога | Замкнутый loop на квадратной сетке вокруг аула. Длина и изгибы идут из `map_*`. |
| Центр | Аул в центре, no-build область. Это наше отличие от Loop Hero. |
| Размещение | `placement = road | roadside | field`. `roadside` влияет на проход героя, `field` работает через радиус/соседство/доход за круг и не требует соседства с дорогой. |
| Зоны | Дорога и road buffer вокруг нее - no-build. Строим только за кромкой дороги и в дальнем field. |
| Build-слоты | Для первого playable: несколько ближних roadside-слотов за road buffer. Дальние field-слоты нужны как целевое направление большого мира. |
| Внутренняя область | Не строим внутри кольца. Центр занят аулом, выходом героя и читаемостью. |
| Карты | Временно можно сделать карту 1:1 с `tile_id`. Полный `cards.tsv` после проверки постановки. |

## Что должно быть играбельно

Игрок должен за 3-5 минут прожить:

```text
герой идет сам
-> герой получает карту
-> игрок ставит карту
-> тайл влияет на будущий проход
-> герой получает риск
-> герой умирает
-> аул получает ресурс
-> новый герой выходит
-> новый герой подбирает Последнюю Тамгу
```

Если это работает, геймплей уже чувствуется.

## Этап 1. Интерактивные build-зоны

### Реализация

- Показать loop-дорогу на квадратной сетке. Геометрия берется из `map_*` в `balance.ini`.
- Показать road buffer/no-build вокруг дороги: кромка, насыпь, вешки или плотный песок.
- За road buffer создать ближние `roadside` build-слоты.
- Показать дальние `field` клетки как направление большого скроллящегося мира.
- Свободная buildable-клетка должна иметь `base_decor_id`, а не выглядеть пустым квадратом.
- Buildable-клетка должна быть кликабельной.
- Слот должен подсвечиваться, когда в руке выбрана карта.
- Нельзя строить в ауле.
- Нельзя строить на дороге, кроме scripted/debug road events.

### Acceptance

- Игрок видит, где нельзя строить: аул, дорога, road buffer.
- Игрок видит, куда можно ставить карту даже при росте/скролле карты.
- Игрок не может поставить карту в неправильное место.
- Поставленный тайл визуально остается на карте.

## Этап 2. Первая карта и рука

### Реализация

- После 2-3 шагов первого героя гарантированно дать карту `saxaul`.
- Игра ставит паузу или замедляет время.
- Игрок выбирает карту в руке.
- Игрок ставит ее в подсвеченный слот.
- Рука MVP: до 5 карт.

### Acceptance

- Игрок получает `Саксаул`.
- Игрок понимает, что карту нужно поставить на карту мира.
- После постановки карта исчезает из руки.

## Этап 3. Эффект поставленного тайла

### Реализация

- `saxaul` действует как первый `roadside` тайл.
- Когда герой проходит связанную дорожную клетку, он получает:

```text
Силы +1
Запасы +1
```

- Для первого playable связь можно сделать простой: ближайший `roadside` влияет на ближайшую `road_cell`.

### Acceptance

- Игрок видит лог эффекта.
- Игрок понимает, что карта помогла через будущий проход, а не как мгновенная кнопка.

## Этап 4. Конец круга и выбор карты

### Реализация

- Когда герой возвращается в аул, показать выбор 1 из 3 карт.
- Первый набор:

```text
Юрта
Камень Тамги
Звериная тропа
```

- После выбора карта попадает в руку.

### Acceptance

- Игрок выбирает стратегию: безопасность, память или риск.
- Следующий круг начинается после выбора.

## Этап 5. Второй круг и первый риск

### Реализация

- Если игрок ставит `wolf_track`, он ставит Звериную тропу и создает Body-check; Волчий след появляется как маркер/лог при срабатывании.
- Если игрок не выбрал риск, на втором круге можно добавить scripted `road_event`.
- Риск должен ощутимо снижать Силы при провале.

### Acceptance

- Игрок видит, что мир стал опаснее из-за тайлов.
- Игрок понимает награду за риск: Слава/Мудрость/карта.

## Этап 6. Смерть, аул, новый герой

### Реализация

- При `Силы <= 0` герой умирает.
- На дорожной клетке смерти появляется `Последняя Тамга`.
- Часть ресурсов идет в аул по текущим процентам из `balance.ini`.
- Показать простой экран результата:

```text
Герой погиб
Аул получил: Запасы X, Мудрость Y, Слава Z
Последняя Тамга осталась на пути
```

- Кнопка: `Новый наследник`.
- Новый герой стартует из аула.

### Acceptance

- Смерть не выглядит как простой game over.
- Игрок видит, что род получил пользу.
- Игрок может сразу начать новый забег.

## Этап 7. Подбор Последней Тамги

### Реализация

- Новый герой идет по тому же кольцу.
- Если он доходит до клетки с Тамгой, она срабатывает:

```text
Мудрость +X
Слава +Y
```

- Тамга исчезает.

### Acceptance

- Игрок понимает: смерть прошлого героя стала целью нового.

## Минимальная версия, если времени мало

Можно резать:

- интро;
- озвучку;
- полноценный `cards.tsv`;
- все синергии;
- апгрейды аула;
- выбор 1 из 3, заменив его фиксированной картой.

Нельзя резать:

- автодвижение;
- кликабельную постановку карты;
- эффект поставленного тайла;
- риск;
- смерть;
- ресурс аула;
- нового героя;
- Последнюю Тамгу.

## Что проверять руками

Тестовый проход:

1. Запустить игру.
2. Дождаться 2-3 шагов героя.
3. Получить `Саксаул`.
4. Поставить `Саксаул` в buildable-клетку за road buffer.
5. Дождаться, пока герой получит эффект Саксаула.
6. Завершить первый круг.
7. Выбрать карту из 3.
8. Во втором круге получить риск.
9. Довести героя до смерти.
10. Убедиться, что аул получил ресурсы.
11. Запустить нового героя.
12. Дойти до Последней Тамги и подобрать ее.

## Итоговый приоритет

```text
build-slots
-> карта в руке
-> постановка Саксаула
-> эффект тайла на будущем проходе
-> выбор карты после круга
-> риск второго круга
-> смерть
-> ресурсы аула
-> новый герой
-> подбор Тамги
```
