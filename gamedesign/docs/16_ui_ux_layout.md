# 16. UI/UX layout

Цель: сделать первый playable удобным для понимания и игры, а не просто набором панелей.

## Источники для UI-логики

- Loop Hero screenshots / SteamDB: https://steamdb.info/app/1282730/screenshots/
- Loop Hero screenshots / MobyGames: https://www.mobygames.com/game/160063/loop-hero/screenshots/
- RPG UI pattern reference / AnyRPG: https://www.anyrpg.org/features/user-interface/
- RPG UI asset pattern reference / CraftPix: https://craftpix.net/product/rpg-game-ui/

## Базовое решение

Основной экран проектируется как **16:9 gameplay frame**.

```text
верх: прозрачный overlay, ресурсы на подложках, круг крупно по центру
лево: чат/боевой журнал событий
центр: карта/дорога/аул/герой + камера + battle bubbles
право: большая панель персонажа, экипировка, текущая схватка
низ: рука карт тайлов
центр поверх: только важные решения
```

Игра не должна выглядеть как сайт с карточками. Сайт GDD показывает мокапы, но реальный игровой UI должен быть привязан к игровому экрану.

## Почему 16:9

16:9 удобен для джемового playable:

- легко проверять в браузере;
- подходит для itch/web;
- дает место под карту в центре;
- позволяет держать чат слева, карты снизу, карту в центре, персонажа справа;
- хорошо масштабируется до fullscreen.

## Safe area

UI привязан не к случайным блокам страницы, а к краям gameplay frame.

Правило:

```text
все важное внутри safe area
карта не перекрывается постоянными панелями
выборы появляются поверх только в паузе
```

На desktop:

- top HUD: 48-64 px, прозрачный overlay;
- left chat/combat log: 260-320 px;
- bottom card hand: 130-180 px;
- right character/combat panel: 320-380 px;
- center map: все оставшееся место.

## Референс: Loop Hero и RPG

Loop Hero важен не только механикой, но и UI-логикой:

- карты лежат в отдельной зоне как основной инструмент игрока;
- герой сам идет по карте;
- карта экспедиции занимает главный визуальный объем;
- экипировка/статы героя живут в отдельной боковой зоне;
- ресурсы и прогресс читаются как постоянный HUD.

RPG/MMO-логика тоже полезна:

- ресурсы и статус обычно сверху или вокруг персонажа;
- action bar часто живет по краю экрана;
- чат/лог часто живет в нижней зоне, потому что это поток текста, а не главный объект действия;
- персонаж и экипировка обычно в боковой панели или отдельном окне;
- модалки поверх gameplay используются только для важных решений.

Для "Песни Тамги" итог:

```text
Loop Hero: карты как основной инструмент + карта главный объект.
RPG: чат/лог снизу + персонаж/экипировка сбоку.
Наша игра: чат слева, карта центр, герой справа, карты снизу.
```

## Основной экран

### Центр

Центр экрана - карта.

На ней должны читаться:

- аул;
- кольцевая дорога;
- герой;
- текущая/следующая клетка;
- свободные build-slots;
- поставленные тайлы;
- Последняя Тамга.

### Верх

Top HUD:

| Элемент | Зачем |
| --- | --- |
| Круг | Игрок понимает прогресс забега. |
| Силы | Главный риск текущего героя. |
| Запасы | Практический ресурс. |
| Мудрость | Память и Тамги. |
| Слава | Прогресс рода. |
| Скорость/пауза | Контроль темпа. |

Top HUD не должен быть тяжелой полосой. Он накладывается поверх верхнего края gameplay frame:

```text
ресурсы = отдельные chip-подложки
круг = крупный центральный маркер
скорость/пауза = компактно справа
```

Карта может немного уходить под верхний overlay, но герой, Тамга и важные build-slots не должны прятаться под ним.

### Право

Правая панель:

- текущий наследник;
- статы `Body / Mind / Spirit`;
- текущая схватка на дорожной клетке;
- цель текущего шага.

Для MVP правая панель показывает только текущий забег:

```text
кукла героя / силуэт
архетип + "Путник рода"
Body / Mind / Spirit
Силы
текущая клетка
текущая проверка / опасность
3-4 пустых слота экипировки, если они не перегружают экран
```

`Реликвия пути` и `Тамга прошлого` не должны выглядеть активными с первой секунды. Их можно показать как locked/empty slots только после объяснения, либо открыть после события:

```text
Реликвия пути -> после получения первой реликвии
Тамга прошлого -> после смерти/появления Последней Тамги
```

`Хранилище`, рюкзак и keepsakes не входят в normal gameplay HUD первого playable. Это экран результата/между забегами.

### Лево

Chat/combat log:

- постоянный журнал автопрохода;
- последние 6-10 строк;
- цвет по типу: gain, danger, death, memory;
- без длинных абзацев.

Журнал объясняет автодвижение и авто-сражения. Он важен не как MMO-чат, а как ощущение живого прохождения: игрок видит, что герой сделал сам, что сработало хорошо, что пошло плохо, почему герой потерял Силы и как экипировка/тайлы повлияли на исход.

Почему слева:

- чат хорошо работает как вертикальный поток;
- он не давит карту снизу;
- он не спорит с рукой карт;
- слева его можно читать периферийно, пока герой идет.

### Низ

Рука карт тайлов:

- до 5 карт в руке;
- выбранная карта подсвечена;
- доступные слоты на карте подсвечены;
- если карту нельзя поставить, UI говорит почему;
- новые карты приходят из событий/конца круга и попадают в эту же зону.

Почему снизу:

- карта в руке снизу ощущается как карточная рука игрока, а не как editor-палитра;
- это ближе к Loop Hero;
- горизонтальная рука хорошо читает 5 карт;
- игрок действует картами снизу вверх: карта -> слот на поле.

## Состояния экрана

### 1. Normal run

Герой идет, карта в центре, персонаж/бой справа, чат/лог слева, рука карт снизу. Игрок может выбрать карту и поставить ее, если есть допустимый слот.

Герой не пошаговый. Игрок не кликает "ход" и не выбирает каждое действие героя. Движение идет автоматически в реальном времени или в ускоряемом авто-темпе. Пауза появляется только на решениях: поставить карту, выбрать карту, подтвердить смерть/нового наследника.

### 2. Card placement

Игрок выбрал карту. Игра может идти медленно или стоять на паузе. Доступные слоты подсвечены. Недоступные слоты не спорят цветом с доступными.

### 3. Card choice

Конец круга. Игра на паузе. В центре выбор 1 из 3 карт. Фон карты остается видимым, чтобы игрок помнил контекст.

### 4. Death

Игра на паузе. В центре death panel:

- герой погиб;
- где появилась Последняя Тамга;
- что получил аул;
- кнопка нового наследника.

Смерть не должна быть просто game over.

### 5. New heir

Короткая панель выбора/подтверждения нового наследника. Для MVP можно одной кнопкой.

## UX-правила

1. Карта всегда главный объект.
2. Карты снизу, потому что это карточная рука игрока, а не editor-палитра.
3. Чат/боевой лог слева, потому что это вертикальный поток событий.
4. Герой, экипировка и текущая схватка справа, потому что это RPG/Loop Hero зона персонажа.
5. Пауза только на решениях.
6. Нет постоянных модалок поверх карты.
7. Любой выбор должен иметь понятный результат до клика.
8. После постановки карты игрок должен увидеть связь: карта -> слот -> будущий эффект.

## Ответ по логу и чату

В Loop Hero нет постоянного RPG-чата в привычном MMO-смысле. Есть:

- системные подсказки;
- текстовые окна/диалоги в особых моментах;
- сообщения/обратная связь по действиям;
- визуальные изменения чисел, карт и экипировки.

Но для "Песни Тамги" чат-лог нужен сильнее, чем в Loop Hero, потому что герой действует сам. Если не показывать подробный поток, игрок будет видеть только результат, но не путь к нему. Референс по ощущению ближе к Capybara Go: текстовый поток делает автосражение живым и показывает, что было хорошо, что плохо, где сработал предмет или тайл.

Фиксируем постоянный **chat/combat log**:

```text
6-10 видимых строк
снизу слева
короткий факт + результат + причина
без больших абзацев
```

Пример:

```text
Путник сам идет к восточной клетке.
Звериная тропа: Body check провален, Силы -2.
Одежда смягчила песчаный урон: -1 вместо -2.
Саксаул впереди: можно поставить карту помощи.
На песке проступает Последняя Тамга.
```

Лог не заменяет карту. Карта показывает где происходит событие, правая панель показывает текущего героя и бой, а лог объясняет последовательность и последствия.

## Battle bubble

Сам бой/check показываем маленьким баблом прямо над клеткой, где он происходит.

```text
Звериная тропа
Body 2 vs 4 · fail
Силы -2
```

Правило:

- bubble привязан к клетке карты;
- 1-3 строки максимум;
- живет 1.5-3 секунды или пока идет событие;
- следует за клеткой при движении камеры;
- не заменяет чат и правую панель;
- не должен перекрывать постановку карт.

Разделение ролей:

```text
карта + bubble = где и что случилось прямо сейчас;
правая панель = подробности текущего боя/check;
чат слева = история и последствия.
```

## Камера

Для MVP камера нужна, потому что пустыня должна расти и давать пространство для прокачки.

```text
pan по карте
zoom in/out
кнопка возврата к аулу/герою
герой сам идет, камера не управляет героем
```

Камера не делает игру пошаговой. Это инструмент обзора и строительства: игрок двигает взгляд по пустыне, выбирает карту тайла и ставит ее в доступную клетку. Герой продолжает идти сам.

## Что важно сейчас

Для первого playable важны только элементы, которые помогают прожить забег:

| Элемент | Почему сейчас |
| --- | --- |
| Карта | Главный объект игры: путь, аул, герой, слоты, Тамга. |
| Рука карт снизу | Главный инструмент игрока. |
| Ресурсы забега | Игрок должен видеть результат пути. |
| Силы | Главный риск героя. |
| Круг | Главный прогресс внутри забега. |
| Персонаж справа | Статы, текущий риск, место под реликт/Тамгу. |
| Чат/боевой лог слева | Объясняет автодвижение и авто-сражения без постоянных пауз. |
| Battle bubble | Показывает бой прямо на клетке, где он происходит. |
| Death panel | Показывает смерть как переход к наследованию. |

## Что важно для аула потом

Аул важен, но не должен перегружать первый gameplay UI. Точнее, стартовая форма - **стойбище рода**, а дальняя мета - рост до аула, укрепленного поселения, степного города и восточной столицы.

Для post-playable:

| Элемент аула | Где лучше жить |
| --- | --- |
| Апгрейды аула | Отдельный экран между забегами. |
| Постройки аула | Центр карты визуально, но не большая панель во время движения. |
| Ресурсы аула | Death panel и экран между забегами. |
| Наследники | Экран выбора/подтверждения после смерти. |
| Реликты | Правая панель героя + экран результата. |
| Большое дерево прогресса | После первого playable, не в основном HUD. |

Правило:

```text
во время пути UI обслуживает путь;
между забегами UI обслуживает аул.
```

Мета-дуга:

```text
стойбище рода
-> родовой аул
-> укрепленный аул
-> торговое поселение
-> степной город
-> восточная столица
-> ханство / султанат / каганат
```

В gameplay frame это видно как центр карты и небольшие визуальные изменения. Полноценный экран развития аула/столицы - между забегами.

## MVP UI checklist

Playable UI готов, если игрок без объяснения понимает:

- где герой;
- сколько у него Сил;
- какой сейчас круг;
- какие карты в руке;
- куда можно поставить выбранную карту;
- что произошло в последние секунды;
- почему событие прошло хорошо или плохо;
- почему герой умер;
- что получил аул;
- как начать новым наследником.

## Что не делать сейчас

Не делать:

- сложное меню аула на основном экране;
- инвентарь героя;
- отдельную боевую сцену;
- десятки всплывающих тултипов;
- декоративные панели, которые съедают карту;
- длинные текстовые окна на каждое событие.
