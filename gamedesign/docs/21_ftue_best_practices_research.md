# 21. FTUE best practices research

Дата: 2026-06-06

Цель: собрать практики FTUE и применить их к первому playable игры **Песнь Тамги**.

## Источники

- Roblox Creator Hub, Onboarding: https://create.roblox.com/docs/production/game-design/onboarding
- GameAnalytics, 10 Tips For A Great First Time User Experience: https://www.gameanalytics.com/blog/tips-for-a-great-first-time-user-experience-ftue-in-f2p-games
- GameAnalytics Docs, Funnels: https://docs.gameanalytics.com/products-and-features/analytics-iq/funnels/
- GameDeveloper, Best practices for a successful FTUE: https://www.gamedeveloper.com/design/best-practices-for-a-successful-ftue-first-time-user-experience-
- Barnett et al., First Time User Experiences in Mobile Games: https://www.open-access.bcu.ac.uk/5878/1/ftue240418.pdf

## Выводы из источников

### 1. Игрок должен начать играть быстро

GameAnalytics и GameDeveloper сходятся на одном: первые минуты критичны. Нельзя начинать с барьеров, длинных меню, учетных записей, рекламы, длинных объяснений или системной энциклопедии. Игрок должен быстро увидеть тему и сделать действие.

Для нас:

```text
темный экран 4-6 сек максимум
-> аул/дорога сразу в кадре
-> герой выходит из аула
-> через 1-2 минуты игрок уже ставит Саксаул
```

### 2. FTUE должен показать ценность игры за 2-3 минуты

GameAnalytics отдельно подчеркивает, что игрок должен быстро понять, почему игра стоит внимания. Не нужно объяснять всю игру, но нужно показать главный кайф.

Для нас главный кайф:

```text
герой идет сам
-> я ставлю тайл
-> тайл срабатывает позже
-> мир меняется из-за моего решения
```

Значит первый playable обязан довести игрока до эффекта Саксаула, а не остановиться на факте постановки карты.

### 3. Учить нужно в контексте, а не текстом

Хорошая FTUE не перечисляет правила до игры. Она дает игроку ситуацию, где правило становится очевидным.

Для нас:

- не писать заранее “roadside работает на ближайшую road cell”;
- показать подсветку допустимой клетки;
- поставить Саксаул;
- подсветить связь Саксаул -> дорожная клетка;
- дать эффект при проходе.

Текст должен объяснять только то, что уже произошло или нужно для ближайшего действия.

### 4. Одна новая идея за раз

Слишком много систем в первые минуты создает когнитивную перегрузку. Progressive disclosure нужен особенно для нашей игры, потому что у нас есть:

- автономный герой;
- аул;
- дорога;
- road buffer;
- roadside;
- field;
- карты;
- рука карт;
- лог;
- статы;
- смерть;
- Тамга;
- наследники.

Порядок раскрытия:

```text
1. Аул и герой.
2. Герой идет сам.
3. Мир дает ресурс.
4. Игрок ставит один roadside-тайл.
5. Тайлы срабатывают позже.
6. Конец круга дает выбор.
7. Только затем объяснять field.
8. Только после риска объяснять смерть/Тамгу.
```

### 5. Первая карта должна быть безопасной, но не слишком ценной

Первое действие должно быть понятным, безопасным и не выглядеть как “редкая награда, которую я сейчас потрачу неправильно”.

Для нас это подтверждает замену Оазиса на Саксаул:

| Карта | Почему не/да |
| --- | --- |
| Оазис | Слишком ценная фантазия для первого действия; игрок может бояться потратить. |
| Саксаул | Обычная помощь пустыни: тень, хворост, малый бонус, хорош для обучения. |

### 6. FTUE должна давать чувство успеха

GameAnalytics выделяет positive reinforcement: игрок должен почувствовать, что сделал правильно. Для нас это не просто `+1`, а короткая причинная цепочка.

Обязательный момент успеха:

```text
Саксаул поставлен
-> герой дошел до связанной клетки
-> Саксаул подсветился
-> Силы +1, Запасы +1
-> лог подтвердил результат
```

Если игрок не видит эту цепочку, первый интерактив провален.

### 7. Пауза только на решениях

Наш герой идет сам, поэтому лишние модалки особенно опасны. Они ломают Loop Hero-ритм.

Пауза нужна:

- первая карта;
- постановка карты;
- выбор 1 из 3;
- смерть/итог;
- новый наследник.

Пауза не нужна:

- обычный ресурс;
- срабатывание Саксаула;
- успех/провал проверки;
- обычная строка лога.

### 8. Цель должна быть видимой

Roblox onboarding рекомендует держать цели заметными в мире или UI. Для нас цель в первой сессии не “пройти всю игру”, а “понять следующий шаг”.

Микроцели FTUE:

| Момент | Видимая цель |
| --- | --- |
| Выход из аула | Дойти до дороги. |
| Автоход | Понять, что герой идет сам. |
| Карта Саксаул | Поставить в подсвеченную клетку. |
| После постановки | Дождаться прохода героя. |
| Конец круга | Выбрать 1 из 3 карт. |
| Второй круг | Пережить риск или понять смерть. |

### 9. FTUE нужно измерять как funnel

GameAnalytics docs рекомендуют воронки для onboarding: шаги, completion, churn/drop-off. Даже для джема стоит заложить события.

Минимальная FTUE funnel-схема:

```text
ftue_intro_start
ftue_aul_revealed
ftue_aul_exit_started
ftue_road_entry
ftue_first_resource
ftue_card_saxaul_found
ftue_saxaul_selected
ftue_saxaul_placed
ftue_saxaul_triggered
ftue_lap_1_complete
ftue_first_choice_opened
ftue_first_choice_selected
ftue_first_risk_seen
ftue_first_death_or_near_death
ftue_new_heir_started
ftue_last_tamga_picked
```

## Ревью текущего FTUE

### Что уже хорошо

- Первый тайл заменен на Саксаул: это лучше для обучения.
- Путь `aul_exit -> road_entry -> loop_walk` правильно показывает, что герой из аула.
- Production cards на сайте уже содержат текст, арт, анимацию, UI, данные.
- Появился `road_buffer`, что нужно для читаемости дороги.
- `field` зафиксирован как часть большого мира, а не как отложенная декорация.

### Главный риск

Сейчас FTUE может попытаться объяснить слишком много:

```text
road buffer
roadside
field
base decor
Саксаул
карты
лог
аул
круг
выбор 1 из 3
смерть
Тамга
новый наследник
```

Решение: в первые 3 минуты field показывать визуально, но не требовать от игрока field-постановки. Первое действие только `roadside` Саксаул. Field раскрыть на выборе после первого круга через Юрту или Камень Тамги.

## Рекомендованный FTUE порядок

### Segment A: 0:00-1:00, “дом и путь”

```text
intro_dark
-> desert_reveal
-> aul_exit
-> road_entry
```

Учить:

- где аул;
- герой выходит из аула;
- герой идет сам.

Не учить:

- field;
- синергии;
- смерть;
- прокачку аула.

### Segment B: 1:00-3:30, “мое первое влияние”

```text
loop_walk
-> resource_gain
-> card_saxaul_found
-> place_saxaul
-> saxaul_trigger
```

Учить:

- карта в руке;
- подсветка допустимой клетки;
- road buffer как запрет;
- Саксаул срабатывает позже.

### Segment C: 3:30-5:30, “первый стратегический выбор”

```text
lap_complete
-> choose_1_of_3
```

Учить:

- Юрта/Камень Тамги = field;
- Звериная тропа = roadside;
- разные карты имеют разные зоны.

### Segment D: 5:30-10:00, “риск и наследование”

```text
second_loop
-> risk
-> death_or_near_death
-> last_tamga
-> new_heir
```

Учить:

- риск может быть выгодным;
- смерть не конец;
- Тамга связывает попытки.

## Что добавить на сайт следующим

Нужен не еще один текстовый блок, а интерактивный/визуальный FTUE storyboard:

1. 4 горизонтальные фазы:
   - Дом и путь.
   - Первое влияние.
   - Первый выбор.
   - Риск и наследование.
2. В каждой фазе:
   - мини-карта;
   - активная UI-зона;
   - строка лога;
   - действие игрока;
   - состояние игры.
3. Для Segment C отдельно показать:
   - Юрта подсвечивает field;
   - Камень Тамги подсвечивает field;
   - Звериная тропа подсвечивает roadside;
   - road buffer не подсвечивается никогда.

## P0/P1/P2 правки

### P0

- Убрать все оставшиеся “Оазис как первая карта” из рабочих документов.
- В FTUE явно указать: первая постановка только `roadside` Саксаул; field виден, но не обязателен до конца первого круга.
- Добавить FTUE funnel event ids в GDD/brief для Code.

### P1

- На сайте показать Segment C: выбор 1 из 3 с разной подсветкой placement.
- В production cards добавить “не показываем/не объясняем сейчас” для каждой фазы, чтобы не перегружать.
- Для road buffer добавить визуальный negative feedback: “здесь кромка пути, строить нельзя”.

### P2

- Подготовить варианты текста для ошибочного клика.
- Подготовить 2-3 варианта скорости первого круга.
- Добавить “skip intro” и “replay tutorial hint” в будущие UX notes.
