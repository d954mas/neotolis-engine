# Engine Principle Catalog

The measurable form of the engine's philosophy for lens 1 of the review. Each principle
below is stated as a **checkable rule** (not a vibe), with the exact AGENTS.md / spec
clause to cite, a default severity, the path scope where it applies, and a
compliant (✅) vs violating (❌) example. A finding on this axis MUST cite the rule it
breaks — "feels un-idiomatic" without a catalog rule is not a finding.

Precedence: a documented engine rule overrides generic C/SOLID advice. Where AGENTS.md
endorses something a generic linter would flag (big `#define` caps, long functions
grouped by `// #region`, error returns as public API contract), **suppress the generic
smell**. Skip anything clang-format / clang-tidy / the size tracker already enforces.

## 1. No heap in hot path — P0

**Rule:** flag `malloc` / `calloc` / `realloc` / `free` / `aligned_alloc` / any container
that reallocs, introduced in a hot-path function: frame loop, fixed update, render-item
generation, batching, per-frame resource resolve, dense SoA/ECS iteration.
**Cite:** AGENTS.md §"Performance and hot path" / §"Working principles" (No heap in hot path).
**Scope:** `engine/render*`, `engine/renderers/`, `engine/sort/`, per-frame paths, ECS iteration. **Inverted in the builder** — heap is fine offline (see §4).
✅ frame-scratch allocator, preallocated storage sized by a `#define` cap.
❌ `NtDrawItem *items = malloc(n * sizeof *items);` inside the render-item build loop.

## 2. Fail early — NT_ASSERT correctness — P0

**Rule:** three distinct violations, all P0:
(a) an **error code silently swallows** an invariant breach or broken data that indicates a bug (instead of `NT_ASSERT`);
(b) `assert()` (plain C assert) used for error handling — it vanishes under `NDEBUG`;
(c) a **bounds check or side effect lives inside `NT_ASSERT(...)`** — `NT_ASSERT` compiles to `((void)0)` in the OFF shipping config, so the check/side-effect disappears in production.
**Cite:** AGENTS.md §"Working principles" (Fail early) + the NT_ASSERT-OFF note.
**Scope:** all runtime code. Untrusted/runtime input (parsers, network, pack data) needs a HARD guard, not assert-only.
✅ `NT_ASSERT(slot < cap); arr[slot] = v;` (check and use separate) · error return `NULL` for "resource not found" (documented API contract).
❌ `NT_ASSERT(arr[i++] == expected);` (mutation vanishes in OFF) · `if (bad_data) return NT_ERR;` where bad_data means a builder bug (should assert).

## 3. Explicit over implicit — P1/P2

**Rule:** flag hidden behavior a caller cannot see at the call site: a silent fallback that
masks a failure, a hidden global/singleton mutated as a side effect, implicit type/format
conversion, "magic" that runs without the game asking. P1 if it changes behavior silently;
P2 if it only obscures.
**Cite:** AGENTS.md §Philosophy (Explicit over implicit) / docs/spec/core/principles.md.
**Scope:** all engine code.
✅ game calls `nt_render_pass_begin(...)` explicitly; order is game code.
❌ a renderer that auto-inserts a sort pass "for convenience" when the game didn't request it.

## 4. Runtime simplicity — no parsers, builder does heavy work — P1

**Rule:** flag source-format import / parsing / heavy validation added to the **runtime**.
The builder does heavy work offline; the runtime loads packs, checks magic/version/type,
and resolves. Heavy validation belongs in the builder (as `NT_BUILD_ASSERT`), not runtime.
**Cite:** AGENTS.md §Philosophy (Prebuilt assets) + §"Working principles" (Builder validates).
**Scope:** runtime = `engine/`; builder = `tools/builder/` (opposite rule — validate hard there).
✅ builder bakes glyph geometry; runtime reads the baked blob.
❌ runtime linking a TTF/PNG parser to import a source asset on load.

## 5. Tiny size — P1

**Rule:** flag new heavyweight dependencies, `<stdio.h>`/printf-family, or format libraries
pulled into the **runtime** binary; large static tables that could be built offline. Binary
size is tracked per PR — a review flags size-principle violations the tracker can't attribute
(e.g. a new TU that will grow once used).
**Cite:** AGENTS.md §Philosophy (Tiny size) + §"Change rules".
**Scope:** runtime `engine/`, examples shipped to web.
✅ compile-time table generated by the builder, `#if`-gated debug tools.
❌ pulling in a general-purpose JSON/regex lib for a runtime feature.

## 6. Platform abstraction — P1

**Rule:** flag a module calling a browser / OS / GL API directly instead of going through
the engine wrapper (`engine/platform/`, `engine/window/`, `engine/graphics/`, `engine/fs/`,
`engine/http/`, `engine/time/`).
**Cite:** AGENTS.md §"Working principles" (Platform abstraction).
**Scope:** every module except the wrapper that owns the platform call.
✅ `nt_time_now()` in a system.
❌ `emscripten_get_now()` / raw `glBindBuffer` called from `engine/ui/`.

## 7. Data-oriented where useful — P2 (scoped)

**Rule:** renderer and components should be SoA, dense iteration, typed handles. But this is
**scoped** — input, window, and app are deliberately simple structs; do NOT flag them for
"not being data-oriented". Flag the reverse: an AoS/pointer-chasing pattern added to the
renderer or a dense component storage.
**Cite:** AGENTS.md §"Working principles" (Data-oriented … Not everything).
**Scope:** `engine/render*`, component storages ONLY.
✅ `NtTransform` stored SoA, iterated densely.
❌ `struct Sprite { Sprite *next; ... }` linked list walked per frame in the renderer.

## 8. Engine/game boundary — P1

**Rule:** flag game responsibility leaking into the engine, or vice versa. Engine owns
platform/memory/entities/resources/GPU-backend/render-primitives/input/audio. Game owns
gameplay, system order, render passes, sort/batch policy, level logic, content organization.
**Cite:** docs/spec/core/principles.md §"Engine/Game Boundary" (strict) + AGENTS.md §"Change rules".
**Scope:** all engine code.
✅ engine exposes sort keys; the game picks the sort policy per pass.
❌ engine hardcoding a render-pass order or a gameplay-specific batching choice.

## 9. Module composition, not monoliths — P1

**Rule:** flag a monolithic subsystem where the spec wants composable modules; flag a module
reaching into another's internals instead of its interface; flag a real impl linked where a
stub/interface belongs (breaks the interface/impl composition — CI has loud-link gates, but
architectural leaks that pass the gate are still findings).
**Cite:** AGENTS.md §"Change rules" (no monolithic subsystems) + the module-composition convention.
**Scope:** `engine/`, `CMakeLists.txt`, interface/stub/impl targets.
✅ module links the header-only `nt_X_interface`; the exe links real or stub.
❌ `nt_gfx_stub` transitively pulling in a real impl, or a module `#include`-ing another's private header.

## 10. Spec is source of truth — P1

**Rule:** flag code that diverges from the relevant `docs/spec/` chapter **without the
divergence being explicitly flagged** in the change (AGENTS.md forbids silently "normalizing"
behavior by guessing). A flagged, justified deviation is fine; a silent one is a finding.
**Cite:** AGENTS.md §"Source of truth" + the specific `docs/spec/` chapter.
**Scope:** all engine code with a corresponding spec chapter.
✅ "Deviates from docs/spec/assets/resource.md §blob-pins because …" in the PR/commit.
❌ resolve pass double-decrements `blob_ref` where the chapter says the resolve pass is the single owner — with no note.

## 11. Comments: short WHY only — P2

**Rule:** flag multi-paragraph comments, historical narrative ("pre-fix X was Y, commit
abc123 moved it…"), Phase/REVIEW/CHUNK tags, commit SHAs, PR/issue numbers, or "what changed"
narratives in source. WHY-invariants and short safety notes are correct and must NOT be flagged.
**Cite:** AGENTS.md §"Code style" (Comments: short WHY only).
**Scope:** all source. (clang-tidy does not catch this — it is a real review lens, but low severity.)
✅ `// Direct-map avoids hash-table realloc in hot path.`
❌ a 6-line comment narrating the three commits that shaped the function.

## 12. No gold-plating / speculative generality — P2

**Rule:** flag abstraction added for imagined future needs, defensive copies, or universal
machinery where a concrete implementation suffices ("if a decision can be deferred without
loss of base architecture — it is deferred"). Do NOT demand rigor absent from the rest of the
codebase.
**Cite:** docs/spec/core/principles.md §"Simplicity Over Universality" + AGENTS.md §Philosophy (Keep it simple).
**Scope:** all engine code.
✅ a concrete function that does exactly what's needed now.
❌ a plugin registry / callback-vtable layer for a feature with a single call site.
