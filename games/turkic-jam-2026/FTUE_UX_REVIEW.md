# FTUE / UI / UX review — первые 5 минут (release-polish)

Прошёл весь путь игрока вживую через devapi + движковый дамп кадра (`visual_qa.dump`).
Снятые состояния: dawn-reveal, launch, pull, place, бой, событие-кубик, пред-босс,
переход на круг 2, смерть/аул. Ниже — находки по приоритету. Это карта работ для
доводки «понятно и красиво», не финальные правки.

## P0 — Интермиттентный выход окна (исследовано — НЕ дефект кода игры)

1. **Окно игры иногда закрывается само в авто-прогоне (~разово на боссе/долгом ране).**
   Расследовано глубоко:
   - native-debug собран с `-fsanitize=address,undefined` — при крашах **stderr пуст**,
     ASan/UBSan-отчётов нет.
   - `NT_ASSERT` в debug = FULL и печатает «NT_ASSERT failed … file:line» в stderr —
     **сообщения нет ни разу** → asserts не срабатывают.
   - lldb с брейком на `nt_app_quit` / `nt_window_request_close` / `glfwSetWindowShouldClose`:
     инфериор выходит (`status 0` чисто «shutting down», в другом прогоне `-1`)
     **без срабатывания брейков**. Игра не может закрыть окно иначе как через `nt_app_quit`
     (платформенная абстракция, прямых GLFW-вызовов в игре нет).
   **Вывод:** закрытие приходит извне (WM_CLOSE), а не из кода игры → почти наверняка
   нестабильность headless-окна/GL в тестовой песочнице, не баг релиза.
   **Действие:** перепроверить на реальном десктопе (окно в фокусе, нормальный запуск).
   Если там не повторяется — закрыть как non-issue. Кода игры это не касается.

## P1 — FTUE: понятность обучения (после интро)

2. **Нет туторного пальца на шагах pull/place/merge.** Палец есть только на шаге
   «Отправить путника». Уроки мешочка/поля используют только верхнюю панель + пульс-
   кольцо. Непоследовательно — нужен палец+глоу на каждом обучаемом контроле (док 23).
3. **Дублирование подсказок.** На шаге pull одновременно: панель FTUE «Нажми
   «Мешочек»…» и постоянный хинт у мешочка «жми «Мешочек» — вытяни карту». Двойной
   текст — на время FTUE постоянный хинт глушить.
4. **События не объясняются.** Первый кубик («Буря: Выносливость 2 ×2.75 = 5, DC 6 →
   ПРОВАЛ») — стена цифр без объяснения, что такое проверка и что игрок выиграл/потерял.
   Нужен разовый ивент-объяснитель (callout на первом событии).
5. **Видимость зелёной подсветки поля.** Текст «Перетащи карту на зелёную клетку», но
   клетки светятся только во время drag — до захвата игрок не видит, КУДА. Подсвечивать
   buildable-клетки сразу, как карта в руке.
6. **Панель FTUE перекрывает центр карты.** Верхняя панель ложится на мир; по доку 23 —
   маленькая строка-цель у активной зоны + затемнение остального, а не модалка по центру.

## P1 — Полировка интро

7. **Палец подрезается у правого края** на launch-панели — сдвинуть левее/под центр кнопки.
8. **Reveal скромный** (только база вар.2: лёгкая вуаль + строка). Дорастить до
   bloom костра + дрейфующего песка (вар.1) ради «вау».
9. Остальное в интро читается хорошо: прогрессивное раскрытие, send→выход→«Путь ведёт
   его сам», унифицированная кнопка «Отправить путника».

## P2 — Общий UI/UX (весь путь)

10. **Темп слишком быстрый** (подтверждено тобой): клетка-в-клетку ~0.25с; бой
    выжигает небилженного героя (20→5 ХП к боссу круга 1). Замедлить
    `move_seconds_per_cell` + ATB боя под спокойный тон.
11. **Боевой ридаут мелкий и в углу** (компактные бойцы внизу-справа) — для «сердцебиения»
    лупа сделать акцент крупнее/яснее.
12. **Заголовок окна «Neotolis»** (движок), а не «Песнь Тамги».
13. **Событие залипает поверх экрана смерти** (герой умер в середине ивента) — гасить
    in-combat/in-event оверлеи при конце забега.
14. **«СМЕРТЬ» крупным красным** — резко; рассмотреть тон дока «Путь окончен, но имя
    осталось». Панель аула (итог+прокачка+«Отправить путника») — ок.
15. **Статы видны полностью во время FTUE** (панель героя) — можно раскрывать постепенно.

## Что хорошо

- Поток интро (reveal → send → walkout → урок), прогрессивное раскрытие, единая кнопка запуска.
- Событие-кубик показывает математику (хорошая база для обучения).
- Плотный боевой лог = «сердцебиение» читается.
- Перепрокладка круга (Loop Hero) + пред-босс привал.

## Рекомендуемый порядок

P0 краш → P1 FTUE (апгрейд по доку 23: палец+цель+затемнение+invalid-feedback,
объяснитель событий) → замедление боя/темпа → bloom интро → P2 лоск.
