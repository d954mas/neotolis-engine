# Протокол координации: Code ⇄ GDD

Над «Песнь Тамги» работают два агента параллельно:

- **Code** (Claude) — движок, игровой C-код, **схема** конфигов и их загрузчик.
- **GDD** (Codex) — дизайн-документы и **значения** баланса в `config/*`.

## Два интерфейса

1. **Машинный интерфейс — `config/`.** Это граница. Code определяет *схему*
   (поля, типы — см. `config/CONFIG.md`), GDD заполняет *значения*. Code никогда
   не хардкодит баланс; GDD никогда не меняет схему в одиночку.

2. **Асинхронный чат — два append-only лога** (этот каталог):
   - `FROM_CODE.md` — пишет **только Code** (Code → GDD).
   - `FROM_GDD.md` — пишет **только GDD** (GDD → Code).
   Свой файл — дополняешь сверху новой записью. Чужой файл — только читаешь.

## Формат записи (добавляется в начало своего лога)

```
## 2026-06-05 18:40 — <тема>  [STATUS: open|done]
<суть: что сделано / что нужно / вопрос>
→ ref: <ссылка на запись в чужом логе, если это ответ>
```

Обработал запрос из чужого лога — пиши ответную запись в СВОЙ лог с `→ ref:` и,
если уместно, поменяй STATUS исходной мысли упоминанием (не редактируя чужой файл).

## Правила

- **Не хардкодь баланс** в C — только дефолты в `config.c` (как fallback).
- **Смена схемы** конфига = запись в `FROM_CODE` ДО изменения + обновление
  `config/CONFIG.md`. Если новое поле нужно GDD — запрос в `FROM_GDD`, Code
  реализует и анонсирует в `FROM_CODE`.
- **Не лезь в чужой домен:** Code не правит значения в `config/*`, GDD не правит
  `src/` и схему. Нужно — попроси через лог.
- Конфликт/неясность — короткая запись в свой лог, не молча.

## Домены

| Агент | Владеет | Не трогает |
|------|---------|-----------|
| Code | `engine/`, `games/.../src/`, `config/CONFIG.md` (схема), загрузчик | значения в `config/*.ini/*.tsv` |
| GDD  | дизайн-доки, **значения** в `config/*.ini/*.tsv` | `src/`, схему, движок |
